# 校园零食在线购物系统开发总结

## 1. 项目概述

本项目是一个面向校园场景的在线零食购物系统，采用前后端分离架构，覆盖普通用户购物、商家商品管理、管理员后台管理三类角色。项目目标是完成一个具备完整业务闭环的毕业设计系统，包括注册登录、商品浏览、购物车、下单、订单管理、地址管理、商品审核、公告管理、统计分析等核心能力。

项目包含两个独立工程：

- 前端工程：`campus-snack-mall-web`
- 后端工程：`campus-snack-mall`

统一命名信息如下：

- 后端包名：`com.campus.snackmall`
- 数据库名：`campus_snack_mall`
- 前端本地地址：`http://localhost:5173`
- 后端本地地址：`http://localhost:8080`
- API 前缀：`/api`

## 3. 系统架构说明

系统采用前后端分离模式：

1. 前端负责页面展示、路由控制、表单校验、状态管理和接口调用。
2. 后端负责权限鉴权、业务处理、数据持久化和统一结果返回。
3. 数据库存储用户、商品、购物车、订单、地址、公告等业务数据。

### 3.1 角色划分

- 普通用户：注册、登录、浏览商品、加入购物车、提交订单、查看订单、管理收货地址和个人资料。
- 入驻用户（商家）：注册、登录、维护自有商品、查看相关订单、查看统计信息。
- 管理员：登录后台、管理分类、商品、用户、订单、公告、统计数据。

### 3.2 权限控制

后端未引入完整 Spring Security 认证体系，而是采用更轻量的 JWT + 拦截器方案：

- 登录成功后签发 JWT。
- 前端将 token 保存在会话存储中，并在请求拦截器中自动附带 `Authorization: Bearer <token>`。
- 后端通过 [`AuthInterceptor`](../backend/src\main\java\com\campus\snackmall\security\AuthInterceptor.java) 解析 token。
- 使用 `@RequireLogin`、`@RequireMerchant`、`@RequireAdmin` 实现角色级访问控制。

## 4. 已实现的核心功能

### 4.1 认证与用户体系

- 普通用户注册：`POST /api/auth/register`
- 商家注册：`POST /api/auth/merchant/register`
- 普通用户登录：`POST /api/auth/login`
- 商家登录：`POST /api/auth/merchant/login`
- 管理员登录：`POST /api/auth/admin/login`
- 获取当前登录用户：`GET /api/auth/me`
- 退出登录：`POST /api/auth/logout`

实现特点：

- 用户密码使用 BCrypt 加密存储。
- 用户名唯一校验。
- 用户状态禁用后不可登录。
- 登录后返回 token 和用户基本信息。

### 4.2 商品与分类

- 前台商品分页列表：`GET /api/products`
- 商品详情：`GET /api/products/{id}`
- 热门推荐：`GET /api/products/recommend/hot`
- 最新推荐：`GET /api/products/recommend/latest`
- 分类列表：`GET /api/categories`

实现特点：

- 前台仅展示已上架且审核通过的商品。
- 支持关键字、分类、价格区间查询。
- 商品支持图片、价格、库存、销量、描述等信息。

### 4.3 购物车

- 查询购物车：`GET /api/cart`
- 加入购物车：`POST /api/cart`
- 修改数量：`PUT /api/cart/{id}`
- 勾选状态更新：`PUT /api/cart/{id}/checked`
- 删除单项：`DELETE /api/cart/{id}`
- 批量删除：`POST /api/cart/batch-delete`
- 全选/取消全选：`PUT /api/cart/checked-all`

实现特点：

- 购物车项按 `user_id + product_id` 唯一约束。
- 已下架或不可售商品会在后续结算阶段被拦截。

### 4.4 订单

- 创建订单：`POST /api/orders`
- 查询我的订单：`GET /api/orders`
- 查询订单详情：`GET /api/orders/{id}`
- 取消订单：`PUT /api/orders/{id}/cancel`
- 确认收货：`PUT /api/orders/{id}/confirm`

实现特点：

- 下单时从购物车选择已勾选商品。
- 校验订单归属，防止越权。
- 下单时校验商品是否存在、是否上架、是否审核通过、库存是否充足。
- 创建订单后扣减库存、增加销量、删除已结算购物车项。
- 取消订单后回滚库存和销量。
- 订单状态流转受限制，不允许非法跳转。

当前状态机如下：

- `1` 待发货
- `2` 配送中
- `3` 已完成
- `4` 已取消

合法流转：

- 待发货 -> 配送中
- 待发货 -> 已取消
- 配送中 -> 已完成
- 配送中 -> 已取消

### 4.5 用户中心

- 获取个人资料：`GET /api/user/profile`
- 修改个人资料：`PUT /api/user/profile`
- 修改密码：`PUT /api/user/password`

收货地址功能：

- 查询地址列表：`GET /api/user/addresses`
- 新增地址：`POST /api/user/addresses`
- 修改地址：`PUT /api/user/addresses/{id}`
- 删除地址：`DELETE /api/user/addresses/{id}`
- 设置默认地址：`PUT /api/user/addresses/{id}/default`

### 4.6 商家后台

- 商家商品分页：`GET /api/merchant/products`
- 新增商品：`POST /api/merchant/products`
- 编辑商品：`PUT /api/merchant/products/{id}`
- 删除商品：`DELETE /api/merchant/products/{id}`
- 商品上架/下架：`PUT /api/merchant/products/{id}/status`
- 商家订单分页：`GET /api/merchant/orders`
- 商家订单详情：`GET /api/merchant/orders/{id}`
- 商家更新订单状态：`PUT /api/merchant/orders/{id}/status`
- 商家经营概览：`GET /api/merchant/statistics/overview`
- 商家热销商品：`GET /api/merchant/statistics/hot-products`
- 商家订单趋势：`GET /api/merchant/statistics/order-trend`

实现特点：

- 商家新增或修改商品后，商品会回到“待审核 + 下架”状态。
- 商家只能操作自己的商品。
- 已经产生订单记录的商品禁止删除。
- 未审核通过的商品不能直接上架。

### 4.7 管理员后台

- 分类管理：增删改查
- 商品管理：分页、上下架、审核
- 订单管理：分页、详情、状态更新
- 用户管理：分页、启停用
- 公告管理：增删改查
- 统计分析：概览、热销商品、近 7 日订单趋势

管理员接口集中在 [`AdminController`](../backend/src\main\java\com\campus\snackmall\module\admin\controller\AdminController.java) 中实现。

### 6.1 数据表总览

系统当前核心表共 8 张：

1. `sys_user`
2. `sys_user_address`
3. `snack_category`
4. `snack_product`
5. `snack_cart`
6. `snack_order`
7. `snack_order_item`
8. `sys_notice`

### 6.2 各表结构说明

#### `sys_user` 用户表

字段用途：

- `id`：主键
- `username`：用户名，唯一
- `password`：加密密码
- `nickname`：昵称
- `phone`：手机号
- `avatar`：头像
- `role`：角色，取值包括 `USER`、`MERCHANT`、`ADMIN`
- `status`：状态，`1` 启用，`0` 禁用
- `create_time` / `update_time`：创建更新时间

作用：

- 保存普通用户、商家和管理员账户信息。

#### `sys_user_address` 收货地址表

字段用途：

- `user_id`：所属用户
- `receiver_name`：收货人
- `receiver_phone`：收货手机号
- `receiver_address`：详细地址
- `is_default`：是否默认地址

作用：

- 保存用户收货地址列表，支持默认地址。

#### `snack_category` 商品分类表

字段用途：

- `name`：分类名称
- `sort`：排序值
- `status`：分类状态

作用：

- 存储零食商品分类信息。

#### `snack_product` 商品表

字段用途：

- `category_id`：所属分类
- `merchant_id`：所属商家
- `name`：商品名称
- `cover_image`：封面图
- `price`：价格
- `stock`：库存
- `sales`：销量
- `description`：描述
- `status`：上下架状态，`0` 下架，`1` 上架
- `audit_status`：审核状态，`0` 待审核，`1` 已通过，`2` 已拒绝
- `is_deleted`：逻辑删除标记
- `version`：版本字段，预留扩展

作用：

- 存储商品基础数据，同时承载审核和上下架管理。

#### `snack_cart` 购物车表

字段用途：

- `user_id`：所属用户
- `product_id`：商品 ID
- `quantity`：购买数量
- `checked`：是否勾选

关键约束：

- `UNIQUE KEY uk_user_product (user_id, product_id)`

作用：

- 存储用户待结算购物车项目。

#### `snack_order` 订单主表

字段用途：

- `order_no`：订单编号
- `user_id`：下单用户
- `total_amount`：订单总金额
- `status`：订单状态
- `receiver_name` / `receiver_phone` / `receiver_address`：收货信息
- `remark`：备注

作用：

- 存储订单主信息。

#### `snack_order_item` 订单明细表

字段用途：

- `order_id`：所属订单
- `order_no`：订单编号冗余
- `product_id`：商品 ID
- `product_name`：下单快照名称
- `product_image`：下单快照图片
- `price`：成交单价
- `quantity`：购买数量
- `amount`：明细金额

作用：

- 保存订单生成时的商品快照，避免商品后续变化影响历史订单。

#### `sys_notice` 公告表

字段用途：

- `title`：公告标题
- `content`：公告内容
- `status`：状态

作用：

- 用于首页通知、运营公告展示。

### 6.3 初始化数据

数据库脚本默认包含：

- 管理员账号 `admin`

- 初始公告数据

注意：

## 8. 关键实现说明

### 8.1 统一返回结构

后端统一使用以下结构返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

分页接口返回：

```json
{
  "code": 200,
  "message": "查询成功",
  "data": {
    "records": [],
    "total": 0,
    "current": 1,
    "size": 10
  }

```

### 8.2 前端状态管理

Pinia 当前主要承担：

- 登录态维护
- token 与用户信息持久化

### 8.3 请求处理

前端 [`http.js`](src\utils\http.js) 已实现：

- 自动注入 token
- 统一处理非 `200` 业务码
- `401` 时清理登录态并跳转登录页

### 8.4 数据安全与业务保护

当前后端代码中已经体现的保护措施包括：

- 用户名唯一校验
- 密码哈希存储
- 登录角色校验
- 资源归属校验，避免越权访问他人订单、购物车、地址

- 订单取消时恢复库存

## 10. 项目启动方式

1. 创建数据库 `campus_snack_mall`
2. 执行 `backend/campus_snack_mall.sql`

在 `backend` 目录执行：

```bash
mvn spring-boot:run
```

```bash
mvn clean package
```

在 `frontend` 目录执行：

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run build
npm run preview
```

## 12. 当前已知问题与后续优化建议

### 12.2 优化建议

- 补充单元测试、接口测试和前端页面测试。
- 为订单、库存更新补充更严格的并发控制。

- 增加支付、优惠券、评价、收藏、搜索推荐等扩展功能。
- 为管理员和商家增加更完整的看板图表。
- 优化数据库索引与大数据量分页查询性能。
