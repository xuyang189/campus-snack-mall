> **修订说明**：本文档在统一版基础上针对接口安全缺陷、字段不一致、遗漏接口、路由冲突、状态码混用等问题进行了全面修正与补充。新增或修改内容以 `【修正】` 标注，新增接口以 `【新增】` 标注。

## 1. 文档说明

### 1.1 文档目的
本文档用于"基于 Spring Boot 与 Vue3 的校园零食在线购物系统"的前后端接口联调，统一接口地址、请求方式、参数字段、返回格式、状态码说明和联调顺序，保证前端与后端开发协同一致。

### 1.2 项目最终统一信息

- 项目题目：**基于 Spring Boot 与 Vue3 的校园零食在线购物系统**
- 后端项目名：`campus-snack-mall`
- 前端项目名：`campus-snack-mall-web`
- Java 基础包名：`com.campus.snackmall`
- 数据库名：`campus_snack_mall`
- API 基础前缀：`/api`

### 1.3 基础地址

- 前端本地地址：`http://localhost:5173`
- 后端本地地址：`http://localhost:8080`
- 接口基础地址：`http://localhost:8080/api`
- **【修正】图片访问地址前缀：`http://localhost:8080/upload/`（开发环境），生产环境通过前端环境变量 `VITE_IMG_BASE_URL` 配置，数据库中只存相对路径**

### 1.4 认证方式
除注册、登录、商品浏览、公告查看等公开接口外，其余接口默认需要登录。

请求头格式如下：

```http
Authorization: Bearer <token>
```

管理员接口除登录外，必须同时具备 `ADMIN` 角色，否则返回 403。

**【修正】所有涉及用户私有资源的接口（订单、购物车、地址），后端 Service 层必须校验资源归属（token 用户与记录 user_id 一致），防止越权访问（IDOR）。**

## 2. 统一返回格式

### 2.1 成功返回
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

### 2.2 失败返回
```json
{
  "code": 409,
  "message": "库存不足",
  "data": null
}
```

**【修正】业务失败不得统一使用 500，应按实际情况使用对应 code（见 2.4）。**

### 2.3 分页返回格式
```json
{
  "code": 200,
  "message": "查询成功",
  "data": {
    "records": [],
    "total": 100,
    "current": 1,
    "size": 10
  }
}
```

### 2.4 通用状态码约定

| code | 含义 | 典型场景 |
|---|---|---|
| 200 | 成功 | 正常响应 |
| 400 | 参数错误 | 必填项为空、格式不合法 |
| 401 | 未登录或 token 失效 | token 过期、未携带 token、用户已被禁用 |
| 403 | 无权限 | 普通用户访问管理员接口、越权访问他人资源 |
| 404 | 资源不存在 | 商品不存在、订单不存在 |
| 409 | 业务冲突 | 库存不足、用户名已存在、订单状态非法流转 |
| 500 | 服务器内部异常 | 未预期的系统错误 |

## 3. 联调约定

### 3.1 字段风格
前后端统一采用小驼峰风格，例如：`productId`、`coverImage`、`totalAmount`、`receiverAddress`

### 3.2 时间格式
统一返回字符串格式：`yyyy-MM-dd HH:mm:ss`

### 3.3 金额字段
金额统一使用 `decimal(10,2)`，返回时保留两位小数，前端展示使用格式化函数，**以后端返回金额为准，不得由前端自行计算订单金额**。

### 3.4 空值处理
- 列表接口无数据时返回空数组 `[]`
- 对象接口无数据时返回 `null`
- 分页接口应始终包含 `records`、`total`、`current`、`size`

### 3.5 图片 URL 处理【修正】
- 后端接口返回的图片字段（如 `coverImage`、`productImage`、`avatar`）均为**相对路径**，例如 `/upload/20260325/abc.png`
- 前端封装 `getImageUrl(path)` 工具函数，统一拼接 `VITE_IMG_BASE_URL` 前缀
- 禁止在数据库中存储含域名的完整 URL

### 3.6 token 使用【修正】
- 登录成功后前端将 token 存入 Pinia store（内存）
- 请求拦截器自动在请求头带上 token
- 401 时前端应清理 Pinia 登录状态并跳转登录页
- **不建议将 token 存入 localStorage，建议使用 Pinia + sessionStorage**

## 4. 认证模块

接口前缀：`/api/auth`

### 4.1 用户注册
- 接口：`POST /api/auth/register`
- 是否鉴权：否

#### 请求参数
```json
{
  "username": "student001",
  "password": "abc123",
  "nickname": "安楠",
  "phone": "13800000000"
}
```

#### 参数校验规则【修正：补充具体规则】

| 字段 | 类型 | 必填 | 校验规则 |
|---|---|---|---|
| username | string | 是 | 4~20位，仅字母/数字/下划线 |
| password | string | 是 | 6~20位 |
| nickname | string | 否 | 最长50位 |
| phone | string | 否 | 符合中国大陆手机号格式 |

#### 成功返回
```json
{
  "code": 200,
  "message": "注册成功",
  "data": true
}
```

#### 失败情况
- 用户名已存在 → code=409，message="用户名已存在"
- 参数格式不合法 → code=400，message 说明具体字段错误

---

### 4.2 用户登录
- 接口：`POST /api/auth/login`
- 是否鉴权：否

#### 请求参数
```json
{
  "username": "student001",
  "password": "abc123"
}
```

#### 成功返回
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.xxx",
    "userInfo": {
      "id": 1,
      "username": "student001",
      "nickname": "安楠",
      "phone": "13800000000",
      "avatar": "/upload/avatar/default.png",
      "role": "USER"
    }
  }
}
```

**【修正】登录返回的 `userInfo` 与 `/api/auth/me` 字段保持完全一致，均包含 `phone` 字段。`avatar` 返回相对路径。**

#### 失败情况
- 用户名或密码错误 → code=401，message="用户名或密码错误"（不区分是哪个错误，防止用户枚举）
- 用户已被禁用 → code=401，message="账号已被禁用，请联系管理员"

---

### 4.3 管理员登录
- 接口：`POST /api/auth/admin/login`
- 是否鉴权：否

#### 请求参数
```json
{
  "username": "admin",
  "password": "123456"
}
```

#### 成功返回
与 4.2 结构一致，`role` 为 `ADMIN`。

**【修正】管理员登录接口与普通登录为不同接口，但后端统一从同一张 `sys_user` 表中查询，通过 `role` 字段区分。管理员接口需额外校验 `role=ADMIN`，否则返回 401。**

## 21. 联调注意事项

### 21.1 前后端字段必须一致
- 后端返回 `coverImage`，前端不要写成 `cover_url`
- 图片字段统一为相对路径，前端拼接域名前缀

### 21.2 金额字段不要用浮点随意计算
前端展示金额使用格式化方法，**以后端返回的 `totalAmount` 为准**，不得自行累加计算作为提交参数。

### 21.3 分页字段固定
统一：`current`、`size`、`total`、`records`

### 21.4 状态值统一【修正】
- 订单状态：整数（1/2/3/4），不得使用字符串
- 商品状态：整数（0下架 / 1上架）
- 用户状态：整数（0禁用 / 1正常）

### 21.5 越权防护【新增】
前端不能依赖"不展示按钮"来防止越权，后端必须在 Service 层强制校验资源归属。

### 21.6 管理端与用户端接口分离
避免出现普通用户误调管理员接口。管理端接口路径统一带 `/admin/` 前缀，拦截器统一拦截校验。

## 22. 常见联调问题排查

### 22.1 401 未授权
- token 未携带 / 已过期 / 解析失败
- 用户账号被禁用（status=0）
- 管理员账号尝试通过普通用户登录接口登录

### 22.2 403 无权限
- 普通用户调用 `/api/admin/*` 接口
- 用户访问他人订单、购物车、地址资源（IDOR）

### 22.3 404 接口不存在
- 前端请求路径写错
- 后端 Controller 映射错误
- Vite 代理配置未生效

### 22.4 409 业务冲突
- 库存不足（下单时）
- 用户名已存在（注册时）
- 订单状态流转非法
- 删除有商品的分类

### 22.5 图片不显示
- 检查数据库存的是否为相对路径
- 检查前端 `getImageUrl()` 函数是否正确拼接环境变量
- 检查后端静态资源配置是否正确映射 `/upload/` 路径

### 22.6 跨域问题
开发时后端配置 CORS 允许 `http://localhost:5173`，或前端 Vite 配置代理转发。**生产环境跨域配置不得使用 `*`。**
